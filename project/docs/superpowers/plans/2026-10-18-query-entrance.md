# 词表与语保查询入口改造

**目标：** 两页采用用户选定的居中查询大框，点击查询后平滑滚动到原有顶部查询区；向上滚动自然返回大框。顶部输入框不悬浮，保留原样式和即时查询。模式切换移至条件栏，横屏显示图标与文字，竖屏仅图标。

**实施方式：** 在当前 dev 分支依次完成两个独立步骤，每步验证、CR、定向提交。保留当前未提交的路由、API、sitemap 和已有计划文件，不安装依赖。

## 用户反馈后的纠正（本次执行）

上一版未符合已批准设计：重复输入框、仅淡出独立入口、模式样式被替换、条件未包含在大框内。以下取代原步骤二的错误实现。

- [x] 查询输入仅一个；滚动中间值、终点与逆向滚动保留同一 DOM 输入和条件控件。
- [x] `QuerySearchEntrance.vue` 仅管理同一个 controls 插槽的滚动进度与容器尺寸、留白、表面变化，移除自带输入框。正常文档流，不使用 sticky/fixed。
- [x] 两页原输入参与变形、原条件栏包含在面板内；大框编辑与候选选择不自动提交或收拢，按钮提交并收拢，紧凑状态保留原即时查询。
- [x] `ResultViewSwitcher.vue` 恢复原语保 SVG、背景、圆角、边框、阴影、悬停与选中效果；只增加横屏文字，竖屏恢复 32px 图标按钮。
- [x] 浏览器检查实际两页的起点、中间态、终点与逆向滚动：只有一个输入且 DOM 不替换、条件在面板内、原紧凑样式、桌面文字与竖屏图标、候选及查询时机。
- [x] 测试、定向 ESLint、生产构建、diff CR 后只提交本次修正。

修正验证：7 个相关测试文件共 42 项通过，定向 ESLint 和 web 构建通过。模拟 API 浏览器验证覆盖词表、语保词汇和语法、桌面及三种竖屏尺寸。候选在中间态与输入左边及下沿的定位误差均为 0；独立 CR 的候选跟随和延迟提交问题已修复并复查。语保卡片已有本地筛选完整移动到面板条件栏，保留原绑定、清空、计数及过滤逻辑。
