# 默认分区树与完整路径查询：前后端改造方案

日期：2026-10-14。状态：讨论稿，核心业务决策已逐项确认，接口细节及分步安排待整体审阅。本文只规划改造，不表示已经修改或验证实现。

## 1. 目标与已确认的边界

解决默认分区树依赖前端手动配置、只能展示三级、重名节点选择与展开错误这三个问题。

用户已确认以下规则：

1. RegionSelector.vue 仍是默认分区的树状选择器，保留逐级展开、点击选择、箭头展开、草稿确认和取消的含义。
2. 地图集和音典两种默认树均由后端根据数据库生成，前端不再手改一级名单。
3. 普通新分区自动加入；特殊类别通过后端集中排除。两种体系首版均排除“待处理、歷史音、戲劇、域外方音、現代標準漢語”。
4. 音典“類閩”和地图集“官話”作为普通分区展示。“高肇”和“髙肇”保留各自原字，不自动合并。
5. 默认树只展示数据库已有完整路径及其祖先，不额外维护空分类骨架。
6. 节点身份使用分区体系与完整路径，不新增分区表，不引入持久分区 ID。改名或移动后的旧选择需要重新确认。
7. 查询父级包含该路径本身与全部下级；父子标签独立保留，最终地点去重。
8. 新界面中，唯一名称自动定位；重名必须选定具体路径，未解决歧义时不执行查询。
9. 超出可用空间时分区内容允许横向滚动，顶部确认栏固定，继续保留树状多列交互。
10. 直接改现有 regions 和 /api/partitions 语义，不新增 region_paths 参数或另一套兼容树接口；旧客户端和旧预设需要一起迁移。
11. 保留文本输入查询当前用户提交数据中额外分区的能力。用户数据不混入 RegionSelector.vue 默认树。
12. 当前一级顺序迁移到后端作排序参考，新一级自动追加；子级使用稳定名称排序。排序参考名单不作为可见性白名单。
13. 已选标签平时显示短名称；名称不唯一时逐段补充祖先，直到标签能唯一识别路径，悬停始终显示完整路径。
14. 文本中混合两个体系时保留原文并提示，未统一体系前禁止执行，不自动清空或切换已输入项。
15. 默认树只在刷新整个页面后更新，同一页面内复用已加载的数据，尽量减少请求；不在每次打开选择器或每次执行查询时重复刷新树，不持续轮询。

本次不改查询算法中的音韵业务、权限规则、地点数量限制、用户保存的自定义分区地点集合、无关路由或现有中文文案。仅为上述目标增加必要的提示与布局溢出处理。动态层级是必要改造，不另行拆出递归组件或改成新页面。

## 2. 当前代码与真实数据依据

### 前端

- src/main/components/geo/RegionSelector.vue：map 使用 STATIC_REGION_TREE；yindian 请求 /api/partitions 后按 top_yindian 过滤；状态、事件与 DOM 固定为 lvl1/lvl2/lvl3。
- getChildrenFromTree 按 label 全树搜索，第一个匹配即返回；同名节点的子项可能取错分支。
- toggleLeaf、chosen 高亮、删除和 active 状态均使用 label；同名节点共享选择身份。
- src/main/components/geo/LocationAndRegionInput.vue：同样存在静态树、顶级过滤、旧 options 转换和 regions 字符串数组；它既负责预览，又把分区传给真实查询页面。
- src/main/components/geo/RegionInputMode.vue：建议项已有路径，但选择建议时只插入 name，丢失父级；其父组件还将文本分区用于查询用户提交数据。
- src/composables/data/usePartitionCache.js：只缓存转换后的音典树，旧白名单裁剪会影响其他消费者；没有按 mode 区分的新树缓存，也没有数据更新后的重验证。
- public/config.js、public/detail/js/inputpanel.js：存在另一套静态配置与旧树消费者，不能漏掉。

### 后端

- app/routes/geo/get_partitions.py：/api/partitions 只生成音典树，parent 是名称，不是完整路径；没有显式使用 get_query_db。
- app/service/geo/match_input_tip.py 的 read_partition_hierarchy：len(parts) >= 3 时只保留 parts[2]，丢失第四级及更深内容。
- app/service/geo/getloc_by_name_region.py：SQL 版本先查完整值相等，再只对未精确命中的输入按单段名称匹配；父级精确命中后可能不继续包含下级。ORM 版本也是完整值或单段名称匹配。
- 上述解析用于 get_locs、搜索、比较、中古音处理、特征统计、notes、聚类、坐标和用户数据，不能只修 get_locs。
- get_query_db 当前按角色选择数据源，虽然本地 admin/user 常量暂时指向同一文件，改造仍需沿用依赖注入和权限隔离。

## 3. 方案取舍

| 方案 | 收益 | 代价 | 决定 |
| --- | --- | --- | --- |
| 完整路径＋直接迁移现有接口 | 沿用 regions 字符串数组与现有存储，接口概念统一 | 前后端、旧页面与旧预设必须同步迁移 | 用户选择本方案 |
| 完整路径＋新增查询参数和新版树接口 | 保持旧客户端旧语义 | 两套协议与迁移逻辑并存，调用点增加字段 | 用户未选择 |
| 稳定分区 ID＋分区表 | 改名和移动后可保持身份 | 需要数据迁移、分区关系维护与旧路径映射 | 用户未选择 |

完整路径解决本次分支歧义，但不提供跨改名、跨移动的稳定身份。同一体系同一父级下两条完全相同的路径视为同一分区；若未来业务要求区分这种情况，再规划独立 ID。

## 4. 数据模型与接口建议

### 4.1 路径约定

- 继续使用数据库现有 ASCII 连字符作为层级分隔符。例如下江-通泰-南泰-口刁。
- 名称仅用于显示与搜索，完整路径用于查询、删除、选中和展开；region_mode 指定体系。
- 一段路径是根节点的完整路径，不能因此重新降级成“匹配全树同名名称”。
- 不对身份值进行繁简转换、异体字合并或 Unicode 兼容归一化。搜索可以使用繁简变体，但候选输出必须保留数据库原文。
- NULL、空字符串、空路径段与含意外段内前后空白的记录应报告。空值不建树；畸形值不静默改写进树，实施前审计后决定是否单独清理数据。
- 当前本地快照没有空段或段内前后空白。部署前仍须对实际数据做同样审计。
- 名称中若未来允许字面连字符，需要另行定义转义或迁移；本次遵循已有数据库格式。

### 4.2 GET /api/partitions

现有接口改为统一返回默认树，支持 region_mode=map 或 yindian；省略 mode 时仍取 yindian。parent 可选，改为完整路径。

建议响应示意：

~~~json
{
  "schema_version": 2,
  "region_mode": "yindian",
  "revision": "opaque-content-revision",
  "max_depth": 4,
  "parent": null,
  "nodes": [
    {
      "label": "下江",
      "path": "下江",
      "depth": 1,
      "children": [
        {
          "label": "通泰",
          "path": "下江-通泰",
          "depth": 2,
          "children": [
            {
              "label": "南泰",
              "path": "下江-通泰-南泰",
              "depth": 3,
              "children": [
                {
                  "label": "口刁",
                  "path": "下江-通泰-南泰-口刁",
                  "depth": 4,
                  "children": []
                }
              ]
            }
          ]
        }
      ]
    }
  ]
}
~~~

示意只展示一条四级路径；实际响应必须完整返回全部可见分支，不能截断。叶子统一 children: []，无需冗余 hasChildren 字段。前端判断 children.length。

- parent 未提供：nodes 为所有可见根节点与完整后代。
- parent 提供：nodes 为该路径的直接子节点，子节点仍携带完整后代；depth 仍是绝对深度，parent 回填请求路径。
- max_depth 表示当前默认树的最大绝对深度；空树为 0。
- schema_version 是协议版本，revision 是当前体系、数据内容与展示策略共同决定的数据版本，两者不混用。
- 未知 mode 或畸形路径返回 422；parent 不在可见默认树中返回 404；已存在叶子的子节点请求正常返回 nodes: []。
- 新响应不兼容旧对象树消费者，所有已知调用点必须迁移。不能继续套用 STATIC_REGION_TREE 对象枚举或旧 parent 响应格式。
- 响应不输出服务器数据库路径，也不包含用户提交记录。

### 4.3 现有查询中的 regions

regions 仍是字符串数组，元素含义改为完整路径：

~~~json
{
  "locations": [],
  "regions": ["嶺西-類粵-桂林", "下江-通泰"],
  "region_mode": "yindian"
}
~~~

查询匹配规则：数据库分区值等于 P，或以 P 加层级分隔符开头。禁止任意子串、任意路径段、名称兜底匹配。

GET 重复参数接口继续 regions=P1&regions=P2；现有坐标接口继续逗号分隔的 transport，数组内每项仍是完整路径。JSON 请求继续数组。不要为统一 transport 重写成熟业务接口。

路径没有匹配地点时返回该接口既有的空结果格式；不能回退到同名分支。未知或失效路径的提示由前端树校验、名称解析和空结果共同处理。系统路径在用户表中没有数据，或用户路径在系统表中没有数据，均是合法空匹配，不应因为来源不同抛错。

### 4.4 文本名称解析接口

建议新增轻量解析接口 POST /api/partitions/resolve，处理输入便利性，不恢复主查询的旧名称语义。

请求含 region_mode、scope、items。scope 为 default 或 default_and_user；后者在登录后仅读取当前用户的提交记录。items 包含输入文本与明确的 kind（name 或 path），避免根节点名称和单段路径混淆。

~~~json
{
  "region_mode": "yindian",
  "scope": "default_and_user",
  "items": [
    {"text": "桂林", "kind": "name"},
    {"text": "下江-通泰", "kind": "path"}
  ]
}
~~~

逐项响应包含 status、候选 path、label、sources，status 取 resolved、ambiguous、not_found。resolved 返回唯一完整路径，ambiguous 返回完整候选集合，not_found 返回空集合。不用请求整体报错掩盖其他已解析项。

- 名称先按原文匹配所有节点，不能只看叶子；没有原文候选时允许繁简搜索匹配。
- 唯一性按完整的体系与路径判断。相同完整路径同时来自默认库和当前用户时合为一个路径候选，sources 记录两者。
- 路径按完整原文确认，不以最后一段重查。默认展示排除规则控制默认树和基于树的自动建议，不新增数据库查询权限限制；显式手输名称/路径的解析按可访问数据核对，不把隐藏类别自动加入默认树。
- 文本输入查询用户数据时，用户路径索引与默认树分开，用户路径不会传回默认树接口，也不加入 RegionSelector.vue。
- 用户提交记录现有分区字段是“音典分區”，这类额外候选归属 yindian；不凭空引入用户地图集字段。map 请求的用户数据仍可通过已解析地点范围查询，不用末级名称冒充用户表中的完整音典路径。
- 未登录时不读取用户记录；用户范围缓存不能被另一用户、登出状态或默认树复用。
- name 歧义或 not_found 时界面保留输入并提示；阻止关联页面执行依赖该分区范围的查询，不只阻止预览。
- 请求中已经通过树选择得到的路径不再作为名称解析。

此解析接口是配合“唯一名称自动定位”和额外用户分区查询的实现建议，需要与整体方案一起审阅。不是新增另一套主查询协议。

## 5. 后端实施细节

### 5.1 生成任意深度默认树

读取当前请求 get_query_db 选择的数据源。map 固定映射到“地圖集二分區”，yindian 固定映射到“音典分區”；SQL 列名仅来自这份映射，不接受客户端任意列名。

1. SELECT DISTINCT 对应分区列，减少重复地点记录的处理。
2. 校验非空路径、逐段遍历，补齐每级祖先。
3. 在当前父节点下按该段名复用已有节点，不做全树名称查找。
4. 生成 label、完整 path、depth、children；同一路径去重。
5. 按根节点精确名称应用已确认的排除规则，隐藏整个子树。
6. 当前一级优先顺序来自旧 map 根节点顺序和 top_yindian，迁移到专用后端策略模块；新增根按稳定名称顺序追加。
7. 子级按原始名称稳定排序，不使用数据库未声明的返回顺序；不改变字形。
8. 生成 revision，响应完整节点数组。

新树构建建议放在 app/service/geo/partitions.py；排除与排序规则放 app/common/partition_policy.py。避免把新规则继续堆入 match_input_tip.py。这是本次必要的模块边界建议，实施前以整体方案批准为依据。

### 5.2 路径查询

- 调整 query_dialect_abbreviations 与 query_dialect_abbreviations_orm 的分区过滤，所有共享调用链取得相同路径语义。
- SQL 使用等值 OR 分隔符边界前缀；若采用 LIKE，必须转义 %、_ 和转义符，并显式指定 ESCAPE。
- SQL 参数化；只对字段映射使用固定标识符。不要把用户路径拼接成 SQL。
- 无论 P 是否已有直接归属记录，都要同时查询其后代，消除现有精确命中后漏掉后代的问题。
- ORM 限定当前 user_id、现有存储标记与现有权限条件，应用相同路径谓词；不要扫描他人数据构建名称索引。
- 多路径的查询范围取并集。保留已有直接地点处理与结果合并约定，只去重地点，不删父子选择。
- 用路径索引确认父子关系时按路径段边界，不能用简单 startsWith(P)。例如甲-乙不包含甲-乙丙。
- 树展示继续覆盖当前库中的路径，不因现有 get_locs 的字表存储过滤而把整类移出树。显示存在但没有可用查询地点时遵循现有空结果提示。

### 5.3 审计所有服务与路由

| 区域 | 已发现入口或服务 | 要检查的内容 |
| --- | --- | --- |
| 地点与坐标 | routes/geo/get_locs.py、get_coordinates.py | 参数、预览、主库与用户库共同查询 |
| 默认树 | routes/geo/get_partitions.py | mode、parent、数据源、响应格式、错误 |
| 字与调搜索 | service/core/search_chars.py、search_tones.py；routes/core/search.py | 路径传递、空结果与缓存 |
| 音韵与中古音 | phonology2status.py、status_arrange_pho.py、new_pho.py；对应 routes 与 schemas | regions 的新语义穿透，不改音韵算法 |
| 比较 | service/core/compare.py；routes/core/compare.py | 所有比较分支、父级展开与已有地点缓存 |
| 统计 | service/core/feature_stats.py、对应 schemas/routes | 特征与音节统计使用同一范围 |
| notes | service/notes.py、routes/notes.py | 筛选范围与分页不受其他业务变化影响 |

实施时重新全局搜索调用点，不能把这份清单当作将来代码不会变化的保证。只更改与分区语义有关的地方。

### 5.4 缓存与后端性能

- 分区语义改变后，凡缓存过“分区到地点解析结果”的后端 key 必须增加语义版本或清除；仅把 regions 字符串加入 key 不能解决旧根路径缓存复用问题。
- 重点检查 compare_zhonggu_locations、聚类解析缓存和其他含地区条件的结果缓存；纯字符解析缓存不因为本次改动全部失效。
- 第一版先测完整树的查询与响应体大小，使用现有连接池、线程池运行同步数据库读取，避免在 async 路由里新增阻塞扫描。
- 如需缓存树，key 至少含数据源隔离标识、体系和策略版本；必须能发现数据库替换及事务提交，不能只靠不包含 WAL 变化的主 db 文件 mtime。
- 可先不增加服务端长期树缓存：本地只有数百不同路径，正确更新比额外缓存层更优先。任何优化以真实测量为依据。

## 6. 前端实施细节

### 6.1 RegionSelector.vue

- 保留现有组件和 props/event 名称。selected 与 update:selected 仍是字符串数组，但元素改为完整路径。
- 节点 identity 可以由 JSON.stringify([mode, path]) 派生，它是前端 key，不冒充稳定数据库 ID。
- 用动态列数组取代三个固定层级状态。每列保存节点、活动路径和必要的行位置；不写固定四级上限。
- 直接读取当前节点的 children，展开深度 d 后清掉 d 以下旧列及对应延迟任务，不重新按名称搜索整棵树。
- hover 延迟与箭头立即展开的含义保持。使用序号或请求令牌令旧 hover/异步响应失效；切换体系、关闭弹层和卸载时全部清理。
- chosen、active、删除、确认与草稿同步均按路径判断；父子重名不共享状态。
- 各级仍可点击选中，具有 children 的节点仍有展开箭头。
- 多列内容区域横向可滚动，各列纵向可滚动；固定顶部确认栏，不让标题跟内容滚动。避免 fixed 列脱离滚动容器导致横滚无效。
- 在局部布局中保留已有列宽、间距和视觉基础。必要的滚动容器改造要单独 CR，不能顺带重做配色、按钮、背景和字体。
- 新增或调整样式继续使用 scoped SCSS，在顶部导入全局 mixins，复用已有 tokens、共享样式与布局 mixins。响应方向仅使用项目要求的 max-aspect-ratio: 1 / 1，不引入宽度 media breakpoint。
- 点击列内不应触发外部确认；第 N 列也要被外部点击判断覆盖，不能继续只判断三个 ref。
- Escape 保持取消草稿；点击外部保持现有确认语义；加载失败不作为“空树成功”清空选择。
- 新标签通常显示 label；该名称在当前体系的候选索引中不唯一时，从父级开始逐段补足最短可区分的祖先后缀，必要时显示全路径。判断重名不能只看当前已选项，否则后选另一项会改变先选项的可辨识性。title 始终提供完整路径，删除始终传 path，数据库路径不被显示缩写反向覆盖。

### 6.2 LocationAndRegionInput.vue

- map/yindian 都加载新版默认树；移除这些消费者对 STATIC_REGION_TREE 与 top_yindian 的实际依赖。
- 检查旧 options/cascader 转换是否仍有活跃消费者。只修改本次必要部分，未证明无用前不删除旧代码。
- modelValue.regions、查询预览、真实查询 emit、defineExpose 中的值都保持完整路径，不能预览使用路径而主请求又取标签。
- 默认树模式中，旧名称预设先解析成唯一路径；歧义时保持待确认状态，禁止误查。
- 文本模式中，文本是用户输入，解析后的 canonical regions 是查询值，两者状态分开；不得在尚未解析时 emit 原名称作为有效查询范围。
- 对外提供或沿用 runDisabled 状态，所有关联运行按钮须真正检查它；歧义、解析中、失效输入不能只禁预览。
- 现有地点数限制、超限时恢复上一次选择、直接地点、自定义地点集合合并、预览列表和地点分区映射都继续保留。快照内容改为路径，不改限制策略。
- 系统分区为空时，直接地点和已选自定义地点集合仍能按现有方式查询。
- 输入已改变后，旧解析与地点请求结果不得覆盖新状态。

### 6.3 RegionInputMode.vue 与用户数据

- 默认建议源读取同一份新版默认树，递归 flatten 所有深度，保留体系、path、label 和祖先展示信息。
- 搜索支持既有繁简变体，返回身份值保留原文；选择建议写入完整路径，不只写 name。
- 默认与当前用户路径建议分开标记来源；同一完整路径可聚合 sources，但用户数据不进入默认树。
- 名称解析检查完整候选集合，不依赖界面“最多显示十项”的截断结果判断唯一性。
- 手输唯一名称通过解析接口转换；重名显示完整路径候选并阻止执行；未知名称保留文本并提示，不能 silently drop。
- 用户数据路径通过登录用户范围解析；未登录不预加载用户分区。
- 仍保持一个请求使用一个 region_mode。混输两个体系时保留文本、提示用户统一体系并禁止执行；选择建议不能自动切换 mode 后把其他已输入项当成同体系。两个体系存在相同完整路径时，以用户明确选择的 mode 为准，不能只凭字符串猜体系。
- 用户保存的自定义分区名称对应地点集合，仍通过 existing customRegions/customRegionData 逻辑工作，不改成上述 partition path。
- 文本出现一段值时，未通过候选选择的值按 name 解析；通过候选选择的单段根路径标为 path。恢复值时先使用明确的已保存路径信息；旧名称恢复走 name 解析，不能因为恰好等于某个根名称而掩盖歧义。
- 维护输入 token 的解析来源与 kind，避免已选单段根路径在执行前被重解释为同名候选。用户修改对应文本后失效该 token 的已解析身份，再按新输入重新解析；查询 payload 不发送这些 UI 状态。

### 6.4 usePartitionCache.js

- 在现有 composable 内提供按 mode 读取新版树的能力，不新增无必要的通用缓存层。
- 保留 getPartitionData/getPartitionPoints 等无关缓存能力；旧 getYindianTree 仅在所有相关消费者迁移后删除或改名。
- 新树采用页面生命周期内的内存缓存，按协议版本、mode 与数据范围区分，存后端原始规范响应，不存某个消费者自行过滤后的树。不使用会跨页面刷新继续命中的 sessionStorage 作为新树的权威缓存。
- 每个体系在本次页面生命周期第一次实际需要时请求一次，后续打开、组件切换与查询复用结果。整页刷新后内存状态消失，第一次使用重新请求；SPA 路由切换不等同于整页刷新。失败不缓存为成功，用户主动重试可重新发起请求。
- 第一版不做周期轮询、每次打开刷新、执行前刷新或 HTTP 304 改造。名称解析在输入改变且没有已解析结果时仍可发起必要请求，同一未变 token 的结果在页面内复用，执行时不重复解析。
- 同一 mode 并发请求合并；map/yindian 请求互不覆盖。使用局部令牌防止切换体系后旧响应替换新树。
- 整页刷新并取得新 revision 后核对恢复的已选路径。失效时保留可见提示、阻止误查，不自动映射到同名新分区。页面未刷新期间后端数据变化可能使旧路径返回空结果，应提示用户刷新或重新选择，不以名称兜底。
- 用户数据解析缓存按用户隔离，登录、登出与切换账号时清理；默认树数据也遵循现有角色数据源隔离。
- 新 key 不复用 __YINDIAN_TREE_CACHE__；只清理与本次协议有关的旧 key，不批量清空其他缓存。

## 7. 旧值、失效路径与发布

- 新客户端主查询只发送完整路径；旧纯名称通过解析接口得到唯一候选后迁移。不能在 backend 主解析中恢复全树同名合并作为兼容。
- 仓库预设逐个核对实际树。歧义不能猜第一条；应向用户确认预设指向的分支，或让该预设进入明确待确认状态。
- 查询草稿、组件 model、Vue 到旧详情页传值均审计。查询 payload 仍用完整路径字符串；保存或恢复时明确路径语义版本，旧名称值需要按本方案重新解析。
- 旧路径改名或移动后，不存在时提示失效；保留输入供确认，不自动删掉、不匹配最后一段、不自动合并异体字。
- 仅保存一个字符串无法普遍区分“旧名称”与“新的单段根路径”，因此需要给持久化草稿或跨页面消息加轻量的 regions_semantics: path-v2 标记，或沿用容器已有的 schema/version 字段。这个标记用于恢复判别，不是新增查询参数；主请求仍只有现有 regions。没有标记的旧草稿按旧名称解析，预设则在迁移时写明完整路径。不要在运行时靠字符串长度猜协议。
- 已确认不保留旧协议，因此发布必须协调后端、Vue 静态资源、public/detail 资源以及仍部署的打包客户端。旧代码不能与新接口长期混跑。
- 灰度或错峰发布需要暂停受影响入口或明确版本阻断，不伪装成空结果。不部署未经迁移的旧客户端。
- 新前端遇到 schema_version 不支持时显示数据加载错误，不解析旧对象树；schema_version 能诊断不兼容，不能让旧客户端自动获得新版支持。
- 保留对应前后端部署版本用于一起回滚；不能只回滚一边。实施不涉及删除真实数据或迁移分区表。
- 旧 public 页是否仍对用户提供服务，实施前查部署与嵌入使用。如果仍活跃则必须迁移，不能单方面删除页面。

本地对 tutorialDiceConfig.js 中显式 regions 数组的只读核对已找到唯一映射，例如瓊崖→嶺南-瓊崖、吳化→嶺南-廉吳-吳化、銅容→嶺南-蒼梧-銅容、四邑片→粵語-四邑片。此检索没有覆盖函数参数生成的所有数组或旧 public 预设；实施前还需完整枚举，不据此宣称预设全部无歧义。
