# 自定义分区改造方案：前端

日期：2026-10-14。状态：需求细节已逐项确认，书面方案待用户审阅；本文件不授权开始实现。

配套方案：[后端](../../../../dialects-backend/docs/superpowers/specs/2026-10-14-custom-partitions-design.md)、[预处理](../../../../dialects-build/docs/superpowers/specs/2026-10-14-location-identity-design.md)。三个仓库共用下述身份、归属和版本契约。

## 1. 目标与当前问题

自定义分区同时服务两个用途：在 `LocationAndRegionInput.vue` 快速选点；在 `DivideTab.vue` 的 dot 模式按个人分区着色。维护一套树和成员关系，允许重叠，以主归属解决地图颜色冲突。

现有功能更接近以简称保存的地点集合：没有父子节点、主归属和完整默认回退。用户必须手工建集合，难以围绕现有默认分区逐点修改；重命名和简称变化也缺少可靠身份保护。

本次代码检查发现：

- 自动加载发生在当前 `RegionSelector.vue` 的 `openPopup()`，不宜简单归因于父组件每次挂载。数组为空同时表示尚未加载、加载失败和确实没有分区，入口因此会错误切换为创建行为。
- `customRegionStore.js` 的缓存键 `customRegions` 不区分账号；内存非空会直接命中，绕过持久缓存有效期；并发等待通过轮询结束，不能可靠传递请求失败。列表已经包含成员，部分详情请求重复。
- 旧接口按分区名称更新；编辑时发送新名称可能新建另一组，或覆盖已有同名组。新体系必须按节点 ID 操作。
- 当前选点最终大量使用简称字符串；公共点、独立个人点同名时不能沿用这种身份表示。
- `MapLibre.vue` 当前 dot 分组最多取前三段，且裸层级名称与颜色数组序号不能保证不同父区的同名子区相互独立、颜色在子集之间稳定。

书面方案编写期间，当前代码已增加服务端默认树 `schema_version:2`、完整路径选择及 `usePartitionCache.getDefaultTree` 的账号 / mode 内存请求共享。本方案沿用这些最新改动，不恢复旧静态树；个人缓存仍须补充实际 dataset 及版本隔离。实施前须再次检查用户最新代码，本文不锁定旧行号。

四级默认路径的事实应准确表述：本地后端 `data/query_user.db` 共 4501 条记录，其中 706 条 `音典分區` 有四个非空 `-` 分隔段，涉及 37 条路径，其中 518 条 `存儲標記` 为字符串 `1`。例如米易为 `中上江-荊益-上江-川黔`，松潘为 `中上江-荊益-上江-川北`，滿洲里为 `華北-河北-東北-關外`。这说明默认资料及现有树解析存在第四段，不表示旧自定义集合具备四级结构，也不证明第四段一定代表统一的语言学层级。

## 2. 已确认的产品规则

| 项目 | 规则 |
| --- | --- |
| map / yindian | 共用个人树和归属；没有个人归属时分别继承当前 tab 的默认路径 |
| 重叠 | 同一地点可属于多个节点，恰有一个主归属；任何归属均可选出地点 |
| 层级 | 第一版最多 8 级，节点父子模型可扩展；地点可直属任何父节点 |
| 选择父区 | 包括直属地点和全部后代成员，按永久身份去重 |
| 首次加入 | 自动成为主归属；后续加入不切换主归属 |
| 删除主归属 | 尚有其他归属时明确选接替主归属；全部清空则恢复默认 |
| 恢复默认 | 清空该地点的全部个人归属，保留树节点 |
| 官方更新 | 未修改地点跟随默认更新；已有个人归属不被官方更新改写 |
| 管理范围 | 全部权限可见公共点，以及自己的独立新增点；无音韵、无坐标仍可管理 |
| 保存 | 页面草稿，明确保存 / 取消，离开提示，后端原子校验 |
| 地图 | 保留默认绘图，显式选择个人着色；颜色自动、稳定、沿用现有色板 |
| 迁移 | 预览并由用户确认后启用，保留旧原始数据；重叠、失效、同名逐项处理 |

“完备”通过动态解析实现，不为每个公共点复制一份用户归属：有个人成员就使用全部个人成员，没有则使用当前默认路径，默认路径缺失则进入“未分类”。个人主归属替代默认绘图归属；默认归属不自动变成额外个人成员。

原有“默认分区”入口继续选择官方范围。地点甲从默认 X 改到个人 A，默认 X 仍包含甲；个人视图的继承 X 不再包含甲，个人 A 包含甲。

## 3. 身份与前后端数据契约

新功能使用 `location_ref`：公共点为 `public:<dataset_id>:<location_id>`，独立个人点为 `private:<point_id>`，其中 ID 为 UUID。简称只用于显示、搜索及经过身份解析后的旧业务适配，不用于去重、保存或推断同名归属。

`dataset_id` 来自实际打开的 query 库身份元数据，两个构建源独立维护，不能从登录角色或文件名猜测。当前后端配置中 admin / user 均指向 `query_user.db`，本功能不顺带修改配置。若将来切换到不同身份命名空间，原源的成员保留，但不凭同名自动应用到新源；新源可见地点按自己的已有成员或默认回退解析。map / yindian 切换不属于数据源切换。

给公共点补充音韵或坐标数据沿用公共引用；独立新增点使用个人引用。同名选项显示“公共资料 / 我的新增点”等来源信息。个人新增点已有音典路径可作为 yindian 默认；没有 map 默认时显示“未分类”，不从同名公共点推断。

跨仓库接口采用 `contract_version: 1`，与现有默认树接口的 `schema_version: 2` 独立。所有个人接口需要登录，权限在后端判断。响应和缓存携带 `dataset_id`、`dataset_version`、个人 `revision`；涉及默认回退的派生结果另含 `region_mode`，共享原始节点 / 成员不按 tab 重复保存。

| 建议接口 | 前端用途 |
| --- | --- |
| GET `/api/personal_partitions/context` | 获取契约能力、实际数据源、版本、8 级上限、迁移状态；不等于加载成员树 |
| GET `/api/personal_partitions` | 加载个人节点与成员快照，包含 `revision`；不复制官方全部地点 |
| GET `/api/personal_partitions/locations` | 按当前默认树导航分页取地点和有效归属，包括可用性；支持未分类、自己的独立点 |
| POST `/api/personal_partitions/commit` | 一次保存节点变更和地点最终成员状态，携带 `base_revision` 与数据源版本 |
| POST `/api/personal_partitions/resolve` | 按节点或继承默认路径服务端展开、去重、检查查询可用性和限额 |
| POST `/api/personal_partitions/plot` | 返回 ID 标识的 dot 点、结构化主路径、稳定分组键和缺坐标诊断 |
| POST `/api/personal_partitions/migration/preview`、`activate` | 迁移预览及用户处理后启用，校验预览版本 |

具体请求及校验以配套后端方案为准。`region_mode` 仅影响默认回退，不改变已保存个人节点和成员。

## 4. 选择器手动加载与缓存

保留原按钮位置。一般地点 / 分区选择器打开时不请求个人分区。状态与列表内容分离：

| 状态 | 按钮 / 内容 | 操作 |
| --- | --- | --- |
| idle | “加载自定义分区” | 点击后发起加载 |
| loading | 使用项目通用 inner loading（现有 `.ui-loading--inline`） | 禁止重复触发，共享同一请求 Promise |
| loaded，存在节点 | 沿用原有入口和展开方式 | 已加载数据可直接选择 |
| loaded，无节点 | 显示真实空状态及管理入口 | 再打开不重复加载，不伪装为未加载 |
| error | 错误提示及重试 | 保留有效旧快照但明确标记过期，不当作成功 |

登录判断与原有提示保留。个人管理页、显式个人绘图入口因用户已经进入该功能可以主动加载；手动加载要求针对一般选点弹层，不应迫使独立管理页再点一次。

在现有 store 内调整状态，不提取新 composable：

- 同账号、同实际数据源的调用共享请求，错误传播给全部等待者；请求结束后清理 Promise。
- 缓存键含账号 ID、dataset ID、契约版本；快照记录 dataset version、revision 和缓存时间。map / yindian 的有效归属派生缓存另含 region mode。
- 内存命中也检查有效期；缓存读取仍需验证当前身份上下文，失效可见地重新加载。
- 保存成功清理旧快照并接收新 revision；退出、切换账号立即清理内存及相应持久缓存。旧无账号 `customRegions` 缓存不作为新账号的有效数据。
- 账号切换后旧请求即使迟到，也不得写入新账号状态；用请求上下文或 generation 校验。
- 多页签不静默覆盖，保存冲突保留本页草稿并提供重新加载 / 比较的入口。

## 5. 独立编辑页面

沿用当前 `/auth/regions` 页面身份及 `UserRegionPage.vue`。在页面内部复刻 `PartitionInfoModal.vue` 的递归默认树、展开、搜索、父区选点和直属地点逻辑；不调用该组件，不加 popup 包装，不提供行政区划 tab，不抽组件或重组模块边界。

页面包含当前 map / yindian tab、默认树导航、个人节点编辑区、地点列表及固定保存操作区。横向 / 纵向布局复用现有共享布局，竖屏仅使用 aspect-ratio 断点。节点编辑区是同一套成员体系的目标树，不是第二套集合功能。

每行示意：`☐ 米易 [公共资料] [我的A / 川黔 ★] [补充分区B]`；未修改示意：`☐ 米易 [默认：中上江 / 荊益 / 上江 / 川黔]`。路径徽标可点击修改归属，★ 表示主归属。复选框只选中批量操作对象；点击归属不触发选点。无默认者显示“未分类”。同名节点显示足够的完整路径及来源。

默认树作为稳定导航：修改甲的归属后，甲仍留在原默认导航行，更新徽标即可，避免编辑中突然消失。另有个人树成员视图，用于检查编辑结果；草稿变化时按最终成员计算计数。

旧选择模式按 `存儲標記` 过滤，本编辑页必须覆盖所有权限可见点。被默认导航策略隐藏的根类也需通过“其他默认分类”分支或搜索访问；保留原默认入口的展示策略，但不能因此遗漏个人管理对象。无音韵 / 无坐标以独立可用性标记展示。

单点与批量操作均支持：追加归属、移除指定归属、替换全部归属、设为主归属、恢复默认。批量表单必须明确“追加 / 替换 / 清空”；删除主归属时列出需要接替选择的地点，不按列表顺序猜测。新加入首个成员可自动选主，有成员者保留原主。

个人树可新建、重命名、移动父节点和删除。新节点采用客户端 UUID，使未保存节点可被草稿成员引用，服务器校验最终所有权。根层为第一级；移动子树按最终最大深度校验 8 级、不得形成环。同父同名视为冲突，不自动合并；不同父下同名允许。节点标签中的 `-` 是普通文字，不解析层级。

节点移动 / 改名改变其后代路径，对已关联地点的展示和颜色层级都会产生影响，操作前展示受影响数量。删除非空节点先预览完整子树、成员去向和主归属冲突，用户选迁移或解除后再生成草稿；直接删除一个节点不能隐含删除整个子树。

点击默认路径作为个人目标时，显式执行“复制默认路径为个人分区”：逐段创建或复用用户确认的个人节点，生成独立节点 ID。显示来源，但官方路径变化不移动这些节点。相同默认名称与个人节点不自动混为同一个节点；存在目标冲突时由用户选复用或改名。不能直接把临时默认树键存为永久个人成员。

草稿保留原快照与最终状态，只发送有变化的节点和地点。待保存数量分别显示节点数、地点数，取消撤回全部草稿。切 tab 保留草稿并仅重算默认徽标；切账号不能把旧草稿带到新账号。离开页面 / 刷新提醒未保存更改，不新增未确认的服务器草稿或长期浏览器草稿功能。

保存失败保持草稿：422 定位到地点 / 节点，409 提示版本变化并显示差异，不自动覆盖；网络中断先重新读取 revision，确认是否已经保存，避免重复创建。确认已经成功时接收新快照并取消离开提醒。

## 6. 选点流程与完整个人视图

现有默认输入与默认路径解析保留。新的“我的分区”视图分开展示“个人节点”和“继承的默认节点”，相同标签不合并为同一可点击节点。

- 个人节点选出其直接和全部后代成员，包括非主归属；父子多选、多个归属、显式点多选都按 location ref 去重。
- 继承默认节点只选没有个人成员的地点，范围按当前 tab 路径本身及后代计算。
- 直接输入简称仍走现有默认业务；当需要涉及个人点或同名来源时，引导选择明确身份，不将一个名字展开为不明确的多个点。
- 查询时服务端检查具体音韵功能是否可用，返回无法使用的地点及原因；前端显示匹配总数、可查询数，不把“缺数据”误报为“分区为空”。
- 不把新树总容量设为旧单集合 1000 个地点。保留实际查询权限和请求限额；大树由服务端展开，超限提示缩小范围，不能截断后声称选中了全部。

针对需要个人身份的查询链路增加 `location_refs` 支持，通过后端适配到已有业务。公共引用可在服务端转换成当前简称；独立个人点必须按其个人 ID 取记录，不能转回同名字符串后与公共记录混查。本次不重写全部现有查询接口，但启用个人身份选点前必须全局检查 `LocationAndRegionInput` 的所有消费端。

本次全局搜索得到六处实际使用：`project/src/main/views/menu/QueryPage.vue`、`project/src/main/views/menu/ComparePage.vue`、`project/src/main/views/menu/cluster/ClusterInputPanel.vue`、`project/src/main/components/pho/Countphos.vue`、`project/src/main/views/explore/word/vocabulary/VocabularyTopControls.vue`、`project/src/main/components/map/Tabs/DivideTab.vue`。各自需保留查询范围、历史 / URL 回填、既有补充数据开关及限额；涉及以地点名为 key 的结果缓存和坐标合并也必须支持 ID。全部公共点身份选点需可用；个人点能否执行某功能由该功能既有数据能力决定，缺能力返回具体不可用原因，不偷偷改查同名公共点，也不借此次分区改造新增未授权的音韵计算能力。

## 7. DivideTab 与 dot 绘图

保留现有默认分区绘图选择，增加“按我的分区着色”。地点范围独立：已选地点或全部可见地点；个人着色固定走 dot 分支。`iscustom` 仍表示补充数据选项，不能复用为个人分区开关。

个人分区等级根据有效路径提供 1 至最多 8 级。地点甲主路径只有两级、选择第六级时，使用其第二级节点；直属父区地点不虚构“未细分”的额外个人节点。未修改点使用对应 map / yindian 默认路径，无默认显示未分类。

后端返回每点 `location_ref`、当前名称、坐标、完整结构化主路径、选中等级的 `group_key`、`color_index` 和显示路径。前端不再对个人标签做 `split('-')`。个人节点键包含用户与节点 ID；默认回退键包含 dataset ID、region mode、完整祖先路径；未分类有独立键。不同父下同名节点有不同图例项，必要时显示完整路径。

颜色使用后端契约中的 SHA-256 算法与 `divide-v1` 色板版本，取现有 `project/src/main/config/colors/mapColors.js` 的 `CATEGORY_PALETTE` 20 色索引；节点改名保留 ID，颜色不因名字、点顺序、选点子集变化。移动节点后低层节点自身颜色保持，但选到不同祖先层级时颜色相应变化。色板有限，允许不同节点同色；图例仍按键区分，不承诺无限互异颜色。

有个人非主归属 B 的甲，从 B 选出后仍按主归属 A 着色，图例可解释该规则。没有坐标的点不画，返回并显示跳过数量与原因；自己的补充坐标仍按现有 `iscustom` 语义选择，颜色归属独立。

新 payload 单独分支接入 `MapLibre.vue`，不得覆盖官方旧 payload 或通过裸名称影响旧业务。若后续要统一提升官方绘图等级，需单独界定范围；本轮要求的八级处理先用于个人有效路径，包括其默认回退第四级。

## 8. 旧数据迁移与发布

原组名原样作为一级节点，横杠不拆层级。原 members 全部保留在预览记录，匹配状态按永久身份展示。单归属可自动主，重叠必须选择主；旧简称失效、同名个人点需选择目标，或明确保留为待处理项并确认暂不参与新体系。不能自动丢弃。

迁移还须区分旧自定义数据的公共补充 / 独立新增。无法判断时显示原记录和来源，由用户确认；不因为刚好同名就绑定公共身份。

用户确认激活后同一页面使用新体系，旧表为归档兼容材料，不保持两个可编辑功能。未迁移用户保持现有功能并可进入预览。新前端根据后端能力启用新入口；已激活用户的旧客户端写操作应得到明确升级提示，不能写入看似成功但新体系不读取的旧表。

回滚前端必须考虑已激活账号：旧 UI 不能编辑新树；后端可保持新读取接口和升级提示。数据回滚另需完整备份，不能通过旧 JSON 无损逆向表示八级树和主归属。

## 10. 验收与设计审阅关注点

最小验收场景：甲原默认 X；在 map 首次加入 A，在 yindian 仍是 A 主归属；再加入 B 可从 B 选甲，绘图仍为 A；移除 A 不选接替者不能保存；清空归属后 map 返回 X，yindian 返回其音典默认。默认 X 原入口全程仍包含甲。

其他必要场景：父区直属点与后代并存；第九级创建 / 移动被拒；重名节点路径区分；官方路径更新只影响未修改点；无默认 / 无音韵 / 无坐标区分；改简称后 ID 不变；不可确认改名不套用；同名私有点分开；两页并发保存冲突；网络保存结果未知可核查；当前源切换不自动跨源匹配。

文档阶段只做路径、契约、UTF-8 与 diff 检查，不运行会重新生成 sitemap 的构建。实现阶段使用现有 Vitest 与项目校验脚本，针对上述业务不变量验证；全局检索所有选择器、退出入口、绘图分支后才可宣称覆盖全部。
