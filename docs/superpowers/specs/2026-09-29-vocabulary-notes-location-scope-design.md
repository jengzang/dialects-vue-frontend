# 词表字表注释模式：地点与分区范围设计

## 状态

已于 2026-09-29 确认，等待用户审阅本设计说明。实现开始前需另写实施计划。

## 目标与范围

在 `/vocabulary/view?tab=card` 的顶部控件中保留默认开启的“词表”开关。关闭后进入“字表注释”模式：以 `dialects_user.db` 的 `notes` 原始行按 IPA 和注释搜索，并继续使用卡片展示。

本设计只增加字表注释模式；既有词表的搜索、筛选、表格、地图、路由和视觉行为必须保持不变。

字表注释模式的地点范围采用现有的 `LocationAndRegionInput.vue`，而不是单独制作一个分区选择器。用户可以输入地点、在地图集与音典分区间切换、使用现有个人自定义分区，并在组件中查看解析后的地点清单。地点编辑只更新草稿范围；只有用户明确点击“刷新结果”才会重查注释。

## 已确认的产品决定

| 主题 | 决定 |
| --- | --- |
| 数据源 | 仅 `dialects_user.db` 的 `notes` 表；`notes.rowid` 是返回 `id`。 |
| 路由 | `source=character-notes` 代表字表注释模式；缺少或未知 `source` 保持原词表。字表注释模式强制 `tab=card`，隐藏父级 `page-tab-navigation`。 |
| 卡片 | `簡稱 → location_name`、`漢字 → character`、`音節 → ipa`、`註釋 → notes`；无标准词/释义行。IPA 有原始值时必须显示。 |
| 搜索字段 | `pronunciation`（IPA）和 `detail`（注释）；空值、遗漏或 `all` 表示两者。模式间字段选择与词表状态相互隔离。 |
| 注释搜索 | 支持 1～2 个汉字。FTS5 将 `文白` 规范为查询短语 `"文 白"`，命中原始 `文 白`，但绝不改写卡片中的源文本。 |
| 行去重 | 不按显示内容去重；同一源行同时命中两个字段只返回一次，不同 `rowid` 即使显示内容相同仍都保留。 |
| 空关键词 | 前端不请求 notes 接口并提示输入关键词；直接 API 空关键词返回 400。 |
| 地点范围 | 允许空范围；空范围表示搜索全库有效注释。地点与分区可同时选，沿用现有并集语义。 |
| 范围限额 | 字表注释模式不限制显式地点数、解析后地点数或弹窗选择数；不影响其他页面的既有限制。单页仍分页。 |
| 分区树 | 完全复用现有 `LocationAndRegionInput` 顶层树，不补齐其当前未显示的分区；以后修改统一树即可自然生效。 |
| 重名分区 | 完全继承当前“裸标签”解析与同名标签并集行为，不改为路径值。 |
| 刷新 | `/api/get_locs/` 成功解析后只更新预览。用户点击“刷新结果”才应用地点范围、回到第 1 页并请求 notes。 |

## 方案选择

### 采用：应用原始选择快照

`LocationAndRegionInput` 每次编辑后仍会调用现有 `/api/get_locs/`，用来显示数量、地点预览和地点所属的两类分区。页面不把这个自动解析动作视为搜索动作。

“刷新结果”冻结与该次解析对应的原始请求参数：

```text
{
  locations: [手动地点及自定义分区展开后的显式地点],
  regions: [已选系统分区标签],
  region_mode: 'map' | 'yindian',
  has_scope: true | false
}
```

之后 `/api/vocabulary/notes` 接收同一份 `locations`、`regions`、`region_mode`，在服务端按 `/api/search_chars` 的同一地点匹配和分区展开逻辑解析。选择大分区时不用把整个最终简称列表写进 GET URL；个人自定义分区也会以其已经展开的显式地点传递，无需向 notes 接口暴露用户分区名称或用户数据。

`/get_locs` 与 notes 请求之间可能有短暂的数据差异；两者都以同一数据库、同一解析规则为准，正常情况下解析结果相同。服务器执行第二次解析是有意的：它使 notes 接口本身可以直接、完整地支持地点与分区参数，并防止客户端伪造“已解析”的地点范围。

### 不采用：只传解析后的简称列表

这会让后端略简单，但大分区会让 URL 过长；而且页面并未真正使用 `regions` 参数，不符合接口需要像 `/api/search_chars` 一样支持地点与分区的目标。

### 不采用：扩展 `/api/search_chars`

`/api/search_chars` 的数据表、结果形状和查询目标均不同。把 notes 查询塞入该接口会耦合成熟的查字行为，也不能提供字表注释卡片所需的稳定协议。

## 前端设计

### 页面与控件

1. `VocabularyViewPage.vue` 根据路由的 `source` 维护词表和字表注释两套独立状态。进入字表注释模式时强制卡片模式，关闭词表的位置/行政区、标准词和地图专属筛选控件；切换回词表时不清空原词表状态。
2. `VocabularyTopControls.vue` 在字表注释模式显示：来源开关、关键词输入、仅 IPA/注释的字段设置，以及 `LocationAndRegionInput`。地点详情入口、原有地点/省市筛选、标准词选择、词表专用搜索模式都不显示。
3. 字表注释模式的 `LocationAndRegionInput` 保持原有地图集/音典切换、个人自定义分区、地点预览和详情弹窗。通过新增的可选属性启用“允许空范围”和“跳过地点限额”；默认值维持旧页面行为。
4. 在地点预览之后显示“刷新结果”。范围编辑完成且 `/get_locs` 成功后，若草稿与已应用范围不同，显示“地点选择已变更，刷新后生效”。旧卡片在刷新前继续保留。

### 草稿与已应用范围

页面保存两个明确的范围对象：

```text
draftScope   // 正由输入组件编辑、并已由最新 /get_locs/ 解析确认的范围
appliedScope // 当前 notes 请求所用的冻结范围
```

- 输入组件编辑时只更新 `draftScope`。它的 300ms `/get_locs/` 防抖仍然存在，以便用户看见所选地点；该请求不触发 notes 搜索。
- 成功解析时，组件发出一个附加的 `locationsResolved` 事件，包含原始选择、最终地点列表、地点分区信息及空范围标识。组件必须用递增请求序号丢弃过期的 `/get_locs/` 响应，不能让先发后至的响应替换较新的草稿。
- 空范围不调用 `/get_locs/`；它也必须发出一次成功的空范围解析事件，清除旧预览，并允许刷新。空范围的 `has_scope` 为 `false`。
- 显式选择却解析为零地点时，`has_scope` 仍为 `true`。刷新应发起带原始范围的 notes 请求，结果是空列表；绝不可因为最终地点数组为空而退化成全库搜索。
- 点击“刷新结果”后，页面复制 `draftScope` 到 `appliedScope`、将页码设为 1、使旧 notes 请求失效，并在关键词非空时立刻搜索。关键词为空时只应用范围并显示空关键词提示。
- 关键词或字段配置的正常防抖搜索继续保留，但在地点范围处于脏状态时始终使用 `appliedScope`，不隐式采用 `draftScope`。

### 不限地点的组件改动

当前共享组件会在三处限制地点：`LOCATION_LIMITS` 的解析结果上限、`GET_LOCS_EXPLICIT_LOCATIONS_LIMIT` 的显式地点上限，以及给分区详情弹窗的 `maxSelection`。字表注释模式需以新的 opt-in 属性同时绕过这三处；不能只增加一个 `Infinity` 的 `limitContext`。

该属性默认保持启用限制，因此查字、查中古、音位、比较等已有页面的权限和上限不变。notes 模式不新增用户角色差异。分页（默认 50、最大 200）和请求失效机制仍限制单次传输与前端渲染量，并不限制选择的地点范围。

### 请求与显示状态

- notes 请求、分页“加载更多”和 `/get_locs/` 解析各自有请求序号。切换来源、点击刷新、切换关键词/字段或销毁页面后，旧响应不得覆盖当前状态。
- 刷新按钮在 `/get_locs/` 尚未完成或解析出错时不可点击；空范围和解析为零地点的成功状态可点击。
- “加载更多”只使用 `appliedScope`；加载期间重复点击无效。响应总数为零显示“无匹配结果”，无关键词显示“请输入搜索词”。
- location 标签在注释卡中只显示，不连接到旧词表的地点详情弹窗。

## 后端 API 设计

只新增一个公共、受限流的只读接口：

```http
GET /api/vocabulary/notes
  ?q=文白
  &search_fields=pronunciation,detail
  &locations=广州
  &locations=香港
  &regions=珠三角
  &region_mode=yindian
  &page=1
  &page_size=50
```

### 参数

| 参数 | 规则 |
| --- | --- |
| `q` | 去除首尾空白后必填；空值为 400。IPA 搜索保留内部空白，注释搜索移除所有 Unicode 空白。 |
| `search_fields` | 可重复或逗号分隔；仅 `pronunciation`、`detail`、`all`。缺失、空值或 `all` 表示两者；未知值为 400。 |
| `locations` | 可重复；按现有地点精确匹配规则解析。 |
| `regions` | 可重复；按 `region_mode` 的现有分区规则解析。 |
| `region_mode` | 与 `/api/search_chars` 采用完全相同的 `map`/`yindian` 语义及默认处理。 |
| `page` | 从 1 开始。 |
| `page_size` | 默认 50，范围 1～200。 |

地点和分区参数同时存在时取并集。完全未提供二者时，不添加地点条件；只要提供过任一范围参数、但解析后没有简称，直接返回 `{ items: [], total: 0 }`。

地点的关联路径固定为：

```text
dialects_user.db.notes.簡稱
  = query_user.db.dialects.簡稱
  → 地圖集二分區 / 音典分區
```

接口先复用 `/api/search_chars` 已有的地点与分区解析服务，获得最终简称，再筛选 `notes.簡稱`。notes 表没有分区列，不能直接在它上面过滤分区。

### 搜索与响应

接口仅查询 `註釋` 去首尾空白后不为 `''`、`'_'`、`'-'` 的行。IPA 分支使用转义 `\\`、`%`、`_` 后的字面 `LIKE`；注释分支使用现有 `notes_fts` contentless FTS5 索引。注释词先去除 Unicode 空白，再拆为字符并构造带引号的 FTS 短语；双引号须转义。

两个字段同时选择时，以 `UNION` 合并命中 `rowid`，而不是 `UNION ALL` 或展示字段的 `DISTINCT`。结果固定 `ORDER BY notes.rowid ASC`，先从同一 matched CTE 取总数，再按分页返回。结果形状为：

```json
{
  "items": [
    {
      "id": 519,
      "location_name": "1883廈門",
      "character": "□",
      "ipa": "lo3",
      "notes": "高,原文作“高”白读,应为训读"
    }
  ],
  "total": 1,
  "page": 1,
  "page_size": 50
}
```

接口不可接受客户端传入数据库路径或名称。它不新增 count、地图、自动补全、分区树或 FTS 重建接口。

## 验收与测试边界

### 前端

- 默认词表与其原有筛选行为不变；切换后仅字表注释强制卡片并隐藏父级页签导航。
- 新模式卡片完整显示地点、汉字、IPA、注释，且没有标准词/释义行；相同显示值的不同源行均显示。
- 空范围全库搜索；地点、地图集分区、音典分区、两者并集和个人自定义分区均可在刷新后正确应用。
- 草稿范围变化不改变已显示结果；刷新才重查、重置页码；关键词/字段变化只使用已应用范围。
- 空范围、零解析范围、`/get_locs/` 失败、快速编辑导致的乱序响应、notes 乱序响应、加载更多与模式切换都有稳定状态。
- notes 模式跳过所有三类地点限制，而其他 `LocationAndRegionInput` 使用者仍受原限制约束。

### 后端

- 1 字与 2 字注释、`文白` 与原文 `文 白`、IPA 字面 `%`/`_`、无效注释哨兵、双字段单行命中、源行重复、稳定分页均有测试。
- 无范围返回全库搜索结果；地点范围、两种分区、地点与分区并集、显式范围零解析均有测试。
- 未知搜索字段和空关键词为 400；`page`、`page_size` 非法值被拒绝；接口公开但应用既有限流策略。
- 后端测试会覆盖无地点数量上限的选择路径，并以真实数据库数据量做针对性分页与查询性能检查，而不是以 UI 限额掩盖性能问题。

## 非目标

- 不补齐或重构当前地图集/音典顶层树。
- 不把裸标签选择改为完整路径选择。
- 不改变既有 `/api/search_chars`、词表搜索或其他页面的地点限额。
- 不新增注释表结构、迁移、FTS 重建或数据库选择参数。
